## 环境问题

应用启动时会自动检测运行环境，检测结果集中在设置通用页的环境卡片里。命令类内置工具在 Windows 上通过 Git Bash 提供终端环境，社区自研的 MCP 工具与 AgentApp 多以 Python 编写，需要工具运行环境才能启动，它由 uv 运行时和 uv 管理的 Python 组成。环境卡片会逐项显示检测状态，状态就绪则无需任何操作，缺失时 Git Bash 给出下载链接，工具运行环境可以一键下载，都不需要手动配置环境变量。

工具运行环境的下载在后台进行，切到别的页面也不会中断，进度显示在环境卡片里，装好和失败都会弹出提示，装完自动变成已就绪，不用回到应用重新检测。失败时提示会写明是哪一类问题，点重试会重新下载。提示下载太慢或者网络连不上时，多半是代理没有接管应用的流量，应用不读取系统代理的设置，只开了系统代理的用户把代理客户端切到 TUN 模式再点重试，这种模式会让代理接管整台电脑的网络流量，没有用代理的用户换一个网络再试。提示下载地址暂时不可用时，稍等片刻再点重试。提示安装时出错时，原因已经写进日志，处理办法见[日志与诊断](#日志与诊断)。

## 高频问题

这一节汇总使用过程中的高频问题，按症状逐条给出处理办法。

智能体不回复时，最常见的原因是模型 Key 没有配置或已失效，到设置的模型供应商页确认目标供应商带已配置标记，必要时重新验证。

Key 验证一直失败时，先确认 Key 没有多余的空格与换行，再确认它未过期、未欠费、有对应模型的使用权限，供应商服务波动时稍后再试一次。

语音没有声音时，确认语音服务已配置且聊天页头的语音开关是打开状态，长回复会先总结再播报，稍有延迟属于正常。

工具调不了时，先确认工具已分配给当前角色，见[分配给角色](/docs/mcp-tools#分配给角色)。自研工具要确认工具运行环境已就绪，Windows 上还要确认 Git Bash 就绪，见[环境问题](#环境问题)。OAuth 型工具长时间未用会授权过期，重新走一遍授权即可。

手机连不上主机时，确认主机端隧道处于启动状态、公网地址没有变化，地址变了的话在设备管理里更新，见[设备管理](/docs/remote#设备管理)。

## 日志与诊断

多数问题都要从日志入手定位。日志默认开启，设置的通用页有启用日志开关，不需要时可以关掉，环境安装和商城下载失败这类关键错误不受开关影响，始终会写进日志。日志文件在通用设置的存储路径卡片里，点击日志目录右侧的打开按钮直达，每个日志文件写满 5MB 后换一个新文件接着写，旧的一份会保留下来，取问题发生时段的文件即可。向社区反馈时附上问题时段的日志文件、你的操作系统与应用版本号，版本号在设置的通用页可以查看，日志里可能出现你的文件路径，反馈前注意自行处理敏感信息。

## 联系支持

自己解决不了时可以通过社区渠道求助。应用的问题反馈集中在 GitHub 仓库的 issue 区，提交前建议先搜索是否已有同类问题，写清复现步骤、系统版本与应用版本，并按需附上[日志](#日志与诊断)。Persona Agent 是开源项目，仓库同时欢迎代码贡献与讨论，商城内容的提交与维护在独立的商城仓库进行。商务与合作类事宜可以通过官网页脚的联系方式沟通，功能建议同样欢迎提 issue，标注清楚使用场景会比单纯的功能名更容易被采纳。
